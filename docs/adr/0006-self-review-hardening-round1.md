# review-collaboration 通過第一次正式自我審查（meta-review）後的補強

**Status**: accepted

review-collaboration 設計完成、實測過幾次真實審查後，用它自己審查自己的整體設計（含使用者要求的「規則間是否相悖」檢查），跟 codex 進行 3 輪對話後達成共識（`docs/review-log.md` 有完整記錄）。本文件記錄這次審查產生的、值得永久留存理由的補強決定，逐項小修改本身已直接寫進 `SKILL.md`，這裡記的是「為什麼」。

## 決定

1. **Push back 的理由要跟原始摘要一樣接受查證分類**：Step 1 的二元查證檢查原本只套用在草擬摘要階段，Step 4「決定要不要接受 codex 意見」這個判斷本身沒有對等機制，等於討好傾向可能在這裡重新溜進來而不被抓到。這是自我檢查跟 codex 審查都獨立指出的同一個問題，兩個視角一致，判斷可信度高。
2. **審查清單機制（下限＋開放式跳脫指令）的驗證方式從純理論假設，改為可選的盲掃對照**：高風險主題預設啟用（跟輪數上限覆寫共用「產出者判斷、使用者確認」這套機制，不另立新判準）——如果永遠可選、永遠不做，這個機制就永遠不會被真的驗證過。
3. **可驗證性的做法從「留 manifest 只記模型/時間」加強為「留 manifest ＋ 內容雜湊 ＋ 每輪 verdict 記錄」**：codex 指出光有模型版本跟時間戳，不足以重建「審查了哪份輸入」；加一個雜湊值當 tripwire（不是密碼學等級），可以在需要時比對逐字稿是否被替換，同時仍然不違反 ADR-0001（雜湊是幾個字元，不是內容本身）。
4. **Fix 的重新查證範圍，從「只有新增主張」擴大到「新增或移除/縮小都要重新掃描既有查證清單」**：移除被質疑的部分一樣可能讓原本綁定在那個部分上的假設失效，不能因為是「刪減」就跳過複查。

## 明確拒絕採用的建議（附理由）

- **建立正式風險分級制度去決定輪數上限**：不採用。會再引入一層一樣沒有客觀標準的主觀判斷，維持「產出者可提議、使用者確認」的輕量做法。
- **產出一份完整的最小權限規格文件（機密資料/網路/工具白名單）**：不採用，對目前工具規模是過度工程；改用輕量提醒（涉及真正機密內容時，使用者應在觸發時主動避免讓內容進摘要）取代正式規格文件。
- **要求多審查者三角驗證**：不是這次的新發現，是 ADR-0002 已經記錄、附帶重新評估條件的既知限制，維持原判斷。

## 尚未解決、誠實留下的部分

盲掃機制與清單/跳脫指令的實際效度、5 輪上限是否在各種主題下都校準得宜——這些都還沒有足夠樣本驗證，`SKILL.md` 已加入「已知限制」聲明，要求每累積約 10-20 次真實審查後主動回顧，不是預設它會自動變好。

**2026-08-12 修正（見 [ADR-0012](./0012-reviewcollab-codex-peer-review-hardening.md)）**：本文件第 2 點原文把「同一次呼叫內的盲掃對照」直接稱為驗證方式，但這個做法其實不是真正獨立的盲測——summary 跟 checklist 在同一個 prompt 裡，模型早已看過全部內容，不能單靠這個判斷清單機制到底有沒有增加價值。`SKILL.md` 已改口誠實承認這只是廉價、弱訊號，並加了一個「真正獨立」的做法（獨立 fresh thread 呼叫）當高風險主題的可選加強版。
